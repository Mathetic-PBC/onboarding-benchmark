Provenance for Personal Knowledge

By Tomasz Wierzbicki · September 29, 2026

Data engineering has a mature vocabulary for provenance: entities, activities, agents, derivations. Personal knowledge tools have almost none of it. A note in most apps knows when it was edited and nothing about where its content came from.

Three questions a note should answer

  • Where did this come from? (a chat message, a page in a paper, a meeting)
  • What else came from the same place?
  • What did this lead to?

Import is where provenance is won or lost

If a tool imports a paper from a reference manager and the same PDF from a downloads folder as two items, every later link is split in two. If an import silently drops a fraction of a user's conversations, the trail has holes the user cannot see. Getting import right is less glamorous than a graph view and matters more.

Duplicates versus versions

A copy of a document with three lines changed is not a duplicate. It is a version, and the change is often the most informative thing about it. Tools should group versions and show the difference, never quietly keep one.

The test of a provenance-aware notebook is simple: pick any sentence in your draft and ask where it came from. The tool should answer in one click.
