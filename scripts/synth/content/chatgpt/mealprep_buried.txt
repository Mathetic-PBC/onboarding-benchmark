ok unrelated but im losing my mind. we submitted idetrace to neurips d&b in may. tonight i found that our train/test split is by WINDOW not by student. so 30s windows from the same student are in both train and test. macro f1 is 0.81 but i think its inflated. rebuttal is due in like 5 days. what do i actually do
@assistant
That's a real leakage problem and it's good you caught it before the rebuttal rather than after. Windows from the same student share a lot: typing rhythm, the assignment they're on, their usual error patterns, even the IDE settings. A model can learn "this is student 37" instead of "this is a stuck student," and then test windows from student 37 look easy.

What to do, in order:

1. **Re-split grouped by student id.** Every student's windows go entirely to train or entirely to test.
   ```python
   from sklearn.model_selection import GroupShuffleSplit, GroupKFold

   gss = GroupShuffleSplit(n_splits=1, test_size=0.2, random_state=0)
   train_idx, test_idx = next(gss.split(X, y, groups=df["student_id"]))

   # or for CV:
   cv = GroupKFold(n_splits=5)
   for tr, te in cv.split(X, y, groups=df["student_id"]):
       ...
   ```
   If students take several sessions, group by student, not by session. Sessions from the same student still leak identity.

2. **Assert it.** Add a check so it can't come back:
   ```python
   assert set(df.iloc[train_idx].student_id).isdisjoint(df.iloc[test_idx].student_id)
   ```

3. **Re-run everything that reports a number**: baselines too, not just your model. The ranking between models can change under a grouped split.

4. **Report both numbers in the rebuttal.** Something like: "We identified that our original split allowed windows from the same student in both train and test. Under a student-grouped split, macro-F1 is X (previously 0.81). We will update all tables and release the grouped split." D&B reviewers care a lot about evaluation hygiene. Disclosing it yourself is far better than a reviewer finding it.

5. **Ship the split with the dataset.** For a datasets track, the canonical split file (student-grouped) is part of the contribution. Put `split_by_student.json` in the release and say in the datasheet that window-level splits leak.

Expect the number to drop meaningfully. A drop of 5–10 points is normal when identity leakage is removed.

should test be stratified by label too? some students have almost no stalled windows
@assistant
Use **StratifiedGroupKFold** (sklearn ≥ 1.0). It keeps groups intact while trying to balance label proportions across folds:

```python
from sklearn.model_selection import StratifiedGroupKFold
cv = StratifiedGroupKFold(n_splits=5, shuffle=True, random_state=0)
for tr, te in cv.split(X, y, groups=df["student_id"]):
    ...
```

It can't be perfect because whole students move together, so print per-fold label distributions and report the spread. For the released single split, pick the seed whose test label distribution is closest to the overall one, and document that you did it. Don't pick the seed with the best F1.
