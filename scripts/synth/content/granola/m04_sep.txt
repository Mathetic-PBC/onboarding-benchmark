label_notes: Design review of the Engelbart canvas: trail/locator model, rendering bug, connect screen.
=== notes
### Canvas model

- A **thought** = a block on the canvas (text the user wrote or pinned)
- A **trail link** = thought → source item + locator (chat message id, doc heading/paragraph, PDF page, commit sha)
- Trail panel opens the original at the locator; summaries only as a secondary line, clearly marked
- Suggestions: up to 3 candidate sources per thought, user confirms with one click (confirmation = the "useful recall" event we log)

### Rendering bug

- Canvas re-renders every block when one block's trail changes → visible flicker with >300 blocks
- Cause: trail links stored on the canvas root object, so any change invalidates everything
- Fix: move links into a per-block store keyed by block id; memoize block components
- David to fix before pilot build

### Connect screen (first pass)

- Grid of sources: Claude, ChatGPT, Zotero, Local PDFs, Google Drive, + "Other" (upload a zip/folder)
- Per-source "exclude folders" at connect time (from Elena's IRB point)
- After import: summary card — counts per source, skipped items with reasons, possible duplicates
- Hudson unsure "Other" is clear — revisit after first pilot

### From Ben (yesterday's call)

- His chain for one modeling decision ran git commit → notes.md → a Slack thread → a paper (took him ~40 min to rebuild)
- Quarto documents keep each figure next to its code; he'd want links into a specific chunk, not just the file
- Logged as a future locator type; commit locator already planned

### Action items

- [ ] David — per-block trail store + memoization (fix flicker)
- [ ] Hudson — connect screen mock with exclude-folders + summary card
- [ ] David — log "suggestion confirmed" event with time since connect
